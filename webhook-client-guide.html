클라이언트 연동 가이드

Webhook 채널로 발송한 메시지의 효과를 측정하기 위해 클라이언트가 해야 할 작업. 신규 SDK 설치 없이, 기존 트래킹 SDK로 이벤트 하나를 추가하는 것이 전부입니다.

대상: 클라이언트 개발자 예상 공수 0.5 man-day 신규 SDK 설치 없음 Unity · JS · Android · iOS

01클라이언트의 역할과 범위

무엇을 하고, 무엇은 하지 않는가

Webhook 채널에서 메시지 발송과 보상 지급은 전부 서버가 처리합니다. 클라이언트는 발송 경로에 관여하지 않습니다. 클라이언트가 필요한 이유는 단 하나, 유저가 실제로 열어봤는지를 측정하기 위해서입니다.

작업 범위

항목클라이언트 작업
메시지 발송 · 보상 지급없음 — 서버가 처리
신규 SDK 설치 · 패키지 추가없음 — 기존 트래킹 SDK 사용
푸시 토큰 등록없음 — FCM 채널을 쓸 때만 필요
우편함 UI 신규 개발없음 — 기존 우편함을 그대로 사용
열람 이벤트 리포트있음 — 이 문서의 전부

이 작업을 하지 않으면 — 발송과 보상 지급은 정상 동작합니다. 다만 도달 퍼널이 "발송 → 도달"까지만 채워지고, 열람률을 알 수 없어 캠페인 효과를 측정할 수 없습니다. 다음 캠페인을 개선할 근거가 사라지므로 함께 진행하는 것을 권장합니다.

02선행 조건 — 계정 식별

구현 전에 반드시 확인할 것

운영 플랫폼은 계정 ID를 기준으로 발송 대상을 선정합니다. 채널의 「전송 ID」에 계정 ID 속성을 지정하기 때문에, 클라이언트가 로그인 시점에 계정 ID를 SDK에 알려주고 있어야 합니다.

로그인 처리 (Unity 예시)
// 로그인 성공 직후 — 이미 구현되어 있는지 확인만 하면 된다
TDAnalytics.Login(accountId);

// 로그아웃 시
TDAnalytics.Logout();

이미 애널리틱스를 연동해 이벤트를 수집 중이라면 대부분 되어 있는 부분입니다. 확인 방법은 분석 플랫폼에서 아무 이벤트나 열어 계정 ID 속성이 채워져 있는지 보는 것입니다. 비어 있다면 이벤트가 계정과 연결되지 않아 발송 대상 자체가 잡히지 않으므로, 이 작업이 먼저입니다.

확인 없이 넘어가지 마세요 — 계정 식별이 안 된 상태에서는 열람 이벤트를 올려도 "누가 열었는지"를 알 수 없어 퍼널이 비어 있게 됩니다. 발송 대상 선정에도 영향을 줍니다.

03서버와의 연결 — message_id

클라이언트 단독으로는 구현할 수 없는 부분

열람 이벤트에는 message_id(발송 건 고유 ID)를 반드시 포함해야 합니다. 이 값이 "이 열람이 어느 발송에서 비롯됐는지"를 잇는 유일한 키이기 때문입니다.

그런데 이 값은 운영 플랫폼이 서버로 보낸 것이라, 서버가 메일 데이터에 실어 내려주어야 클라이언트가 알 수 있습니다.

서버팀에 요청할 내용

운영 발송으로 생성된 우편함 메일에 message_id를 저장하고, 메일 목록·상세 조회 API 응답에 해당 필드를 포함해 주세요. 운영 발송이 아닌 일반 메일은 이 값이 비어 있어도 됩니다.

기대하는 메일 API 응답 형태
{
  "mail_id": "m_88123",
  "title": "복귀 보상이 도착했어요",
  "body": "7일 출석 보상을 확인하세요",
  "reward_id": "comeback_pack_01",
  "message_id": "msg_a1b2c3",   // ★ 운영 발송 메일에만 존재
  "expires_at": "2026-08-06T00:00:00Z"
}

클라이언트는 이 값을 화면에 표시하지 않고, 메일 데이터 모델에 담아 두었다가 이벤트를 올릴 때만 사용합니다.

04이벤트 규격

무엇을 언제 올릴 것인가

이벤트명

이름은 자유롭게 정할 수 있지만, 채널의 「도달 퍼널 설정」에 등록한 이름과 정확히 일치해야 합니다. 대소문자와 언더스코어까지 동일해야 하므로, 운영 담당자와 미리 합의하고 시작하세요. 이 문서에서는 mail_opened를 예시로 사용합니다.

이벤트 속성

속성명필수값용도
message_id필수서버가 내려준 발송 건 ID퍼널 연결 키 — 없으면 집계 불가
channel선택"webhook"여러 채널을 쓸 때 구분
mail_id선택우편함 메일 고유 ID서버 로그와 대조
action선택"open" 또는 "claim"단순 열람과 보상 수령 구분

발생 시점

두 가지 중 무엇을 "열람"으로 볼지 기획과 합의해 정하세요. 둘 다 올리고 action 속성으로 구분하는 방법도 좋습니다.

시점의미권장
메일 상세를 열었을 때내용을 확인함메시지 도달 효과 측정에 적합
보상을 수령했을 때실제 행동으로 이어짐전환 측정에 적합

중복 발생 주의 — 메일 상세를 여러 번 열면 이벤트가 여러 번 올라갑니다. 유니크 열람률이 필요하다면 분석 단계에서 유저 단위로 집계하거나, 클라이언트에서 메일당 최초 1회만 올리도록 처리하세요. 어느 쪽으로 할지 기획과 미리 정하는 편이 좋습니다.

05구현 코드

사용 중인 플랫폼의 코드를 참고하세요

Unity (C#)

MailboxUI.cs
using ThinkingAnalytics;
using System.Collections.Generic;

public void OnMailOpened(MailData mail)
{
    // 운영 발송 메일이 아니면(message_id 없음) 이벤트를 올리지 않는다
    if (string.IsNullOrEmpty(mail.MessageId)) return;

    var props = new Dictionary<string, object>
    {
        { "message_id", mail.MessageId },   // ★ 필수
        { "channel",    "webhook" },
        { "mail_id",    mail.Id },
        { "action",     "open" }
    };

    TDAnalytics.Track("mail_opened", props);
}

// 보상 수령까지 구분해서 측정하려면
public void OnRewardClaimed(MailData mail)
{
    if (string.IsNullOrEmpty(mail.MessageId)) return;

    TDAnalytics.Track("mail_opened", new Dictionary<string, object>
    {
        { "message_id", mail.MessageId },
        { "channel",    "webhook" },
        { "mail_id",    mail.Id },
        { "action",     "claim" },
        { "reward_id",  mail.RewardId }
    });
}

JavaScript / 웹

mailbox.js
function onMailOpened(mail) {
  if (!mail.message_id) return;

  ta.track('mail_opened', {
    message_id: mail.message_id,   // ★ 필수

Android (Java)

MailDetailActivity.java
private void onMailOpened(Mail mail) {
    if (TextUtils.isEmpty(mail.getMessageId())) return;

    try {
        JSONObject props = new JSONObject();
        props.put("message_id", mail.getMessageId());   // ★ 필수
        props.put("channel",    "webhook");
        props.put("mail_id",    mail.getId());
        props.put("action",     "open");

        TDAnalytics.track("mail_opened", props);
    } catch (JSONException e) {
        Log.e(TAG, "이벤트 속성 생성 실패", e);
    }
}

iOS (Swift)

MailDetailViewController.swift
func onMailOpened(_ mail: Mail) {
    guard let messageId = mail.messageId, !messageId.isEmpty else { return }

    let props: [String: Any] = [
        "message_id": messageId,   // ★ 필수
        "channel":    "webhook",
        "mail_id":    mail.id,
        "action":     "open"
    ]

    TDAnalytics.track("mail_opened", properties: props)
}

06트래킹 플랜 등록

코드만으로는 끝나지 않는다

새로 만든 이벤트는 트래킹 플랜(이벤트 관리)에 등록해야 분석 화면에서 정상적으로 인식되고 선택할 수 있습니다. 등록하지 않으면 데이터는 들어오지만 리포트에서 이벤트를 찾을 수 없습니다.

등록 대상표시 이름 예시타입
mail_opened메일 열람이벤트
message_id발송 건 ID이벤트 속성 (문자열)
channel발송 채널이벤트 속성 (문자열)
mail_id메일 ID이벤트 속성 (문자열)
action동작 구분이벤트 속성 (문자열)

이 작업은 보통 운영 담당자나 데이터 담당자가 처리합니다. 클라이언트 개발자는 사용한 이벤트명과 속성명 목록을 전달하면 됩니다.

07검증

개발 빌드에서 확인하는 방법

1. 로그 확인

디버그 로그 활성화
// Unity
TDAnalytics.EnableLog(true);

// Android
TDAnalytics.enableLog(true);

// iOS (Swift)
TDAnalytics.setLogLevel(.debug)

// JavaScript — SDK 초기화 시
ta.init({ appId: '...', serverUrl: '...', showLog: true });

메일을 열었을 때 mail_opened가 전송되고, 속성에 message_id가 채워져 있는지 로그에서 확인합니다.

2. 실시간 유입 확인

분석 플랫폼의 디버그 모드에서 테스트 기기의 이벤트가 실시간으로 들어오는지 확인합니다. 계정 ID가 함께 붙어 있는지도 이때 같이 봅니다.

3. 퍼널 연결 확인

운영 담당자가 테스트 발송을 한 뒤, 그 메일을 열어 도달 퍼널에서 발송 → 도달 → 열람이 모두 집계되는지 확인합니다. 여기까지 통과하면 연동 완료입니다.

완료 판정 — 테스트 계정으로 받은 운영 메일을 열었을 때, 도달 퍼널의 열람 단계 숫자가 올라가면 정상입니다. 이벤트는 들어오는데 퍼널이 0이면 message_id 누락이나 이벤트명 불일치를 의심하세요.

08체크리스트와 흔한 실수

놓치기 쉬운 지점

구현 체크리스트

  • 로그인 시 계정 ID가 SDK에 리포트되고 있음 (02장)
  • 서버로부터 메일 데이터에 message_id가 내려옴 (03장)
  • 이벤트명을 운영 담당자와 합의함
  • 메일 열람 시 이벤트 리포트 구현, message_id 속성 포함
  • 운영 발송이 아닌 메일에서는 이벤트를 올리지 않도록 분기
  • 이벤트명 · 속성명 목록을 운영 담당자에게 전달 (트래킹 플랜 등록용)
  • 디버그 로그와 실시간 유입으로 확인
  • 도달 퍼널에서 열람 단계가 집계되는 것 확인

흔한 실수

실수증상해결
message_id를 속성에 넣지 않음이벤트는 쌓이는데 퍼널이 0속성에 추가 (가장 흔한 원인)
이벤트명 오탈자퍼널이 0채널 설정의 이벤트명과 문자 단위 대조
트래킹 플랜 미등록분석 화면에서 이벤트 선택 불가운영 담당자에게 등록 요청
계정 식별 누락이벤트가 유저와 연결 안 됨로그인 시 계정 ID 리포트 확인
모든 메일에서 이벤트 발생일반 메일까지 집계되어 수치 왜곡message_id 유무로 분기
중복 발생 미고려열람률이 100%를 넘음유저 단위 집계 또는 최초 1회 제한
Webhook 채널 클라이언트 연동 가이드 · 코드는 각 플랫폼 SDK 기준 참조 구현입니다. 이벤트명과 속성명은 채널의 도달 퍼널 설정 및 트래킹 플랜과 일치시켜 사용하시기 바랍니다.

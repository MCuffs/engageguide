## 운영 작업 생성 — 실측 구조 (2026-08-03 2차 측정)

### 진입 플로우 (내 목업에 없던 단계)
```
운영 작업 목록 → [＋ 작업 생성]
  → ① 모달 「도달 방식 선택」 (Webhook 도달 / 메시지 푸시 / 클라이언트 도달 3개 카드)
      · 채널이 없는 방식은 회색 비활성 + [채널] 바로가기 링크 노출
  → ② 모달 「Webhook 도달 · 도달 채널 선택」 (검색 + 채널 리스트, 이전/확인)
  → ③ 작성 화면 (#/hermes/task/create)
```

### 작성 화면 = 전체화면 + 좌측 스테퍼
- 상단 바: `‹` 뒤로 · 채널 타입 배지(Webhook) · **작업 이름 입력(80자 이내)** · `UTC-8` · [초안 저장] [저장 후 제출]
- 좌측: 세로 스테퍼 6단계 (현재 단계 강조 + 요약값 표시)
- 우측: 각 섹션이 카드로 세로 나열 (스크롤 연동)

### 6개 섹션과 내용
| # | 섹션 | 구성 |
|---|---|---|
| 1 | **푸시 시점** | 푸시 타입 7종 타일 — 시간 지정-1회 / 시간 지정-반복 / 수동 / 트리거-A 완료 / 트리거-A 완료 후 B 완료 / 트리거-A 완료 후 B 미완료 / 트리거-커스텀 · 푸시 시간 · 승인 시간 초과(자동 종료 / 승인 후 바로 푸시) |
| 2 | **타겟 사용자** | 커스텀 그룹 / 기존 토글 · 사용자 충족 조건 · 사용자 행동 조건 · 사용자 제외 조건 (AND) · **예상 인원 + [예측] 버튼** |
| 3 | **푸시 설정** | **A/B 테스트 활성화** 토글 · 도달 채널 · 피로도 제어 · 화이트리스트(멤버 선택) |
| 4 | **푸시 콘텐츠** | 기본 언어 탭 · 템플릿 필드 입력(0/128) · **[테스트 전송]** |
| 5 | **목표 설정** | 주요 목표 · 설명 추가 · **목표 기간**("성공 수신 후 N일 내 아래 이벤트 실행 시 목표 달성") · 구체적인 규칙 · 조건 추가 |
| 6 | **지표 설정** | 푸시 성공 등 지표 선택 |

### 추가 확인 사항
- 작업 이름은 상단 바에 있음(본문 아님)
- 시간대 표시가 상단에 고정(`UTC-8`)
- 저장은 **초안 저장**과 **저장 후 제출** 2단계

## 실험(Atlas) 화면 구조 실측 — 2026-08-05

`.cn` 콘솔 확인 결과, **실험 영역에는 좌측 사이드바가 없습니다.** 표가 전체 폭을 씁니다.

### 이동 경로
상단 **실험** 드롭다운으로만 이동합니다.

| 그룹 | 항목 |
|---|---|
| 핵심 모듈 | 실험 목록 · 트래픽 레이어 |
| 기본 설정 | 지표 관리 |

**피처 관리는 실험이 아니라 구성 센터(설정 센터) 소속입니다.**
페이지 경로는 `#/atlas/feature/list`(Atlas)이지만 진입 메뉴는 구성 센터이고,
이 페이지에서 활성화되는 상단 메뉴도 **구성 센터**입니다.

### 구성 센터 드롭다운 (그룹 라벨 없는 평면 3항목, 228 × 240)
| 항목 | 경로 |
|---|---|
| 피처 관리 | `#/atlas/feature/list` |
| 시나리오 관리 | `#/hermes/config/items` |
| 채널 관리 | `#/hermes/setting/channel` |

`시나리오 관리`로 들어가면 좌측 사이드바가 있고(구성 항목 · 데이터 분석 · 구성 전략 트리),
페이지 제목은 `구성 항목`, 버튼은 `+ 구성 항목 만들기`입니다.

### 피처 관리 컬럼 (실물)
`피처 파라미터 이름 · 표시 이름 · 상태 · 파라미터 타입 · 기본값 · 값 할당 규칙 · 그룹 · 접속 측 · 비고 · 생성자 · 작업`

- 첫 컬럼은 `Feature 파라미터 이름`이 아니라 **`피처 파라미터 이름`**
- 마지막 정보 컬럼은 `마지막 수정자`가 아니라 **`생성자`**
- 제목 오른쪽에 작은 **보관됨** 링크 (버튼이 아님)

## 가이드 내용 점검 결과 — 2026-08-06

### 실험 투어 확장 (72 → 80단계)
초보자 기준으로 **제출 이후가 통째로 비어 있어** 가이드를 끝까지 따라 해도
실험이 실제로 돌지 않는 상태였습니다. 다음 8단계를 추가했습니다.

| 단계 | 채운 공백 |
|---|---|
| 12–13 코드 연동 | 피처를 만들어도 앱·서버 조회 코드가 없으면 실험이 동작하지 않음. 구버전 앱 대기까지 포함 |
| 68 가드레일 지표 추가 | 42단계에서 4가지 지표 역할을 가르치면서 편집 화면엔 핵심·보조만 있던 모순 해소 |
| 69 필요 표본·기간 산정 | "30일"의 근거. 현재값 → MDE → 군당 표본 → 기간 환산 |
| 72 제출 전 배정 검증(QA) | 운영 투어의 3게이트에 대응하는 실험 쪽 검증 절차 |
| 75 실험 시작 | **제출 ≠ 적용.** 실행 대기에서 시작을 눌러야 배정 개시 |
| 79 일시 중지 / 실험 중지 | 중지 판단 기준과 두 동작의 차이 |
| 80 롤백 | 중지는 신규 배정만 멈춤. 기본값 롤백까지 해야 복구 |

단계 순서는 **실행 시작 → 리포트 → 중지 판단 → 롤백**입니다.

### 단계 번호 자동 부여
단계를 삽입해도 번호가 어긋나지 않도록, `TOURS` 정의 직후 제목의 기존 번호를
제거하고 정의 순서대로 다시 매깁니다. 인트로(첫 `center` 단계)만 번호를 갖지 않습니다.
시나리오 투어(webhook/push/client)에서 중간부터 번호가 사라지던 문제도 함께 해소됩니다.

### 도달 퍼널 표기 통일
세 곳에서 4단계 / 5단계 / 단계명이 서로 달랐습니다. 실제 UI 기준으로 통일했습니다.

**① 예약 푸시 → ② 실제 푸시 → ③ 푸시 성공 → ④ 푸시 클릭**
①~③은 플랫폼 자동 집계, **④만 앱이 올리는 커스텀 이벤트**가 필요합니다.
기존 운영 투어 9단계는 "3단계(도달)는 서버가 리포트"라고 안내해
불필요한 서버 개발을 요구하고 있었습니다.

### 용어를 실물 라벨로 통일
`Feature` → `피처` (한국어 문맥 43곳). 실물 콘솔은 `피처 실험`, `피처 파라미터 이름`을 씁니다.
코드 식별자(`vFeature`, `expFeature` 등)는 그대로 두었습니다.

### 그 외
- 실험 투어 1단계의 데모 프로젝트 ID(1196) 제거
- 21단계 "왼쪽 지표 관리" → 상단 드롭다운 (사이드바 제거 반영 누락분)
- 경로 라벨 `실험 · 피처 관리` → `설정 센터 · 피처 관리`
- 설명 보강: Atlas 용어 정의, 운영 A/B와의 차이, 트래픽 레이어 배타의 구체 사례,
  실험 트래픽 × 그룹 배분 = 실제 노출 비율(50%×50%=25%), 95% 유의성 판정 기준,
  `A100` 슬롯 번호, `값 할당 규칙` 열의 의미

### 미해결
- **실험 상세·편집·리포트 3개 화면은 실물 대조 기록이 없습니다.** 실물 확인은
  실험 목록·피처 관리·시나리오 관리까지만 이뤄졌습니다. 특히 리포트 화면의
  수치·레이아웃은 추정입니다.
- `.io`(사용자·설정 센터) / `.cn`(유저·구성 센터) 용어 선택 미결.
- `m.example` / `m.caution` 46곳은 패널에서 제거된 뒤로 렌더링되지 않는 죽은 코드입니다.
  무해하여 남겨 두었습니다.

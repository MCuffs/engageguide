# Engagement 모듈 도입 가이드 — 기획 초안 (v0.1)

작성일: 2026-07-30 · 대상 프로젝트: Polaris (AE project_id 3)

## 1. 문서 목적과 완료 기준

- **목적**: AE Engage(운영 터치)를 처음 접하는 사람이 이 문서만 보고 "푸시 채널 구축 → SDK 연동 → 테스트 발송 → 첫 운영 태스크 → 효과 확인"까지 완주하게 한다.
- **대상 독자**: AE/Engage를 전혀 모르는 신규 담당자 (운영 기획자 + 클라이언트 개발자 혼합 독자)
- **완료 기준 (이 가이드를 따라 한 사람이 달성해야 하는 상태)**
  1. FCM 채널이 활성화되어 있다
  2. 테스트 기기에서 실제 푸시를 수신하고 클릭 이벤트가 집계된다
  3. 수동 태스크 1건을 발송하고 도달 퍼널을 읽을 수 있다
  4. 피로도·방해금지·허용목록 등 안전장치가 설정되어 있다

## 2. 작성 원칙

- **모든 단계는 콘솔 화면 + ae-cli 명령 병기** — 화면으로 이해하고, CLI로 재현·자동화할 수 있게
- **각 챕터 끝에 "검증" 절 필수** — 무엇이 보이면 성공인지 명시 (list/get/test-send로 확인)
- **역할 표기** — 각 단계에 담당 역할 태그: `[플랫폼 관리자]` `[클라이언트 개발]` `[운영자]`
- **Polaris 실측값 사용** — 가상의 예시 대신 실제 프로젝트(전송 ID `#account_id`, Unity/Android, PH·MY 유저) 기준
- **용어 최소화** — 첫 등장 용어는 한 줄 정의 박스. 채널/태스크/저니/도달 퍼널 등

## 3. 목차 구성 (챕터별 초안)

### CH0. Engage가 무엇인가 (개념, 10분)
- 분석(Analytics)과 운영(Engage)의 관계 — "데이터로 고른 유저에게, 정해진 채널로, 메시지를 보낸다"
- 핵심 개념 지도: 채널 → 태스크(정기/수동/트리거) → 캠페인 → 저니 → 도달 퍼널
- **채널 3종 비교표** (이번 세션에서 검증한 내용):
  | 채널 | 서버 필요 | 닿는 대상 | 용도 |
  |---|---|---|---|
  | FCM | 불필요 | 앱 밖 유저 포함 | 푸시 알림·복귀 유도 (주력) |
  | 클라이언트 | 불필요 | 앱 실행 중 유저 | 인앱 팝업·온보딩 (보완) |
  | Webhook | 필요 | 서버가 정함 | 인게임 메일·커스텀 (후순위) |
- 혼동 주의 박스: 설정센터의 "컨피그 채널"은 운영 터치 채널이 아님 (실제 혼동 사례 기반)

### CH1. 사전 준비 [플랫폼 관리자]
- 필요 권한 확인 (프로젝트 역할)
- Firebase 준비: 프로젝트 생성 → 앱 등록(패키지명) → 서비스 계정 비공개 키 JSON 발급
- ae-cli 설치·로그인: `npm i -g @thinkingai/ae-cli` → `config set-host` → `auth login`
- 검증: `ae-cli auth status`, `ae-cli analysis project info list`

### CH2. FCM 채널 구축 [플랫폼 관리자]
- 콘솔: 채널 이름 / 전송 ID(FCM 토큰 속성) / 서버 개인 키 업로드 / 도달 퍼널 ON / 패스스루 파라미터
- CLI 대응: `engage-setting channel create|get|list|update-status`
- 전송 ID 선택 기준 — SDK 토큰 리포트 전이면 드롭다운에 속성이 없다는 함정 명시 (CH3과의 순환 의존 해소법)
- 검증: `engage-setting channel list`에서 채널 상태 확인

### CH3. SDK 연동 [클라이언트 개발] (Unity/Android 기준)
- 패키지 3종: `ta_unity_sdk`(기존) + `ta_remoteconfig_sdk` + `ta_strategy_sdk`
- 구현 4점 세트: `Init` → `SetPushToken(FCM 토큰)` → `trackPushClick` → `TDStrategy.setClientParam`
- Android 13+ 알림 권한(POST_NOTIFICATIONS) 요청 타이밍 설계
- 커스텀 클라이언트 파라미터 등록: `engage-setting client-param create|list`
- 검증: 디버그 로그 레벨 + 토큰이 유저 속성으로 들어왔는지 확인

### CH4. 안전장치 설정 [플랫폼 관리자]
- 테스트 허용목록: `engage-setting whitelist add|list` (entity_id + source_value)
- 피로도 제어(채널별 일일 상한): `engage-setting channel-touch-limits`
- 방해금지 시간 (기본 22:00~06:00 — PH/MY 시간대 고려 필요)
- 승인 워크플로 (도입 초기엔 OFF 권장 여부 결정 필요 — 미확정 사항 §5)
- 검증: 각 설정 list 명령

### CH5. 첫 발송 — 테스트에서 수동 태스크까지 [운영자]
- 채널 테스트 발송: `engage-setting channel test-send` (허용목록 유저 대상)
- 수신 확인 → 클릭 → 클릭 이벤트 유입 확인
- 첫 수동 태스크: 대상 세그먼트(예: "설치 후 미접속 D1 유저") + 메시지 작성 + 발송
- CLI 대응: `engage-task task ...`, 발송 기록 `engage-task push-record`
- 검증: 발송 건수 = 대상 수, 도달 퍼널 수치 확인

### CH6. 자동화 — 트리거 태스크와 저니 [운영자]
- 트리거 태스크: 서버/클라이언트 트리거 차이, 클라이언트 파라미터 활용 (예: 스테이지 실패 시 팝업)
- 저니(플로우) 기초: `engage-flow flow|node-config|version`
- Polaris 추천 첫 시나리오 3종 (분석 결과 연동):
  1. D1 복귀 푸시 — 설치 후 24시간 미접속 유저 (리텐션 5.2% 문제 직결)
  2. 온보딩 인앱 팝업 — 첫 세션 중 이탈 방지
  3. 휴면 복귀 캠페인 — 3일 미접속

### CH7. 효과 측정 [운영자·분석가]
- 도달 퍼널 읽는 법: 발송→도달→클릭
- 태스크 지표: `engage-task metric`, A/B 테스트 개요
- 리텐션 개선 측정: 처치군/대조군 코호트 비교 (기존 분석 방법론 재사용)

### CH8. 트러블슈팅
- 푸시 미수신: 토큰 리포트/키 설정/알림 권한 체크리스트
- 트리거 미작동: 이벤트 리포트·파라미터 매칭
- 전송 ID 드롭다운이 비어 있음 / 채널 저장 실패 / test-send 실패
- 이번 세션의 실제 혼동 사례: Webhook vs 컨피그 채널 vs 클라이언트 채널

### 부록
- A. ae-cli Engage 명령 전체 레퍼런스 (도메인별 표)
- B. 원클릭 체크리스트 (인쇄용 1장)
- C. Webhook 채널 상세 (인게임 메일 도입 시)
- D. 용어집
- E. **설정센터(컨피그 센터) 가이드** — 운영 터치와의 차이, 컨피그 채널(webhook/client) 등록, 컨피그 항목·그룹·파라미터 관리, 전략·템플릿, 게임 설정값 원격 배포 시나리오. CLI: `engage-scene config-channel|config-item|config-group|config-param|strategy|template`. 터치 채널과의 혼동 방지 비교표 포함

## 4. 제작·배포 계획

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1 | 각 챕터의 CLI 명령을 실제 프로젝트에서 실행·검증하며 집필 (읽기 명령은 즉시, 쓰기 명령은 사용자 확인 후) | 챕터별 마크다운 |
| 2 | 스크린샷 삽입 위치 표시 (콘솔 화면은 사용자 제공 필요) | 이미지 플레이스홀더 |
| 3 | 초심자 리뷰 1회 — 막히는 지점 수집 | 개정판 |
| 4 | 배포: 로컬 마크다운(`engage-guide/`) + Artifact 웹 페이지, (선택) AE 지식베이스 업로드 | 최종본 |

## 5. 미확정 사항 (확인 필요)

1. **채널 범위** — 1차 가이드는 FCM + 클라이언트 채널 2종으로 하고 Webhook은 부록으로 빼는 안. 동의하는지?
2. **iOS 계획** — 현재 Android 100%인데, iOS 출시 계획이 있으면 CH3에 APNs 절 추가 필요
3. **승인 워크플로** — 초기엔 끄고 시작할지, 처음부터 결재 라인을 넣을지 (조직 정책)
4. **저니(CH6) 깊이** — 1차에서는 개요만 다루고 별도 심화편으로 뺄지
5. **스크린샷** — 콘솔 화면 캡처는 제가 접근할 수 없어 사용자 제공이 필요 (필요 화면 목록은 집필 시 정리)
